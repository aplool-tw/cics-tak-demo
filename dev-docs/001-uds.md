## 三、關鍵技術決策（Clarifications）

1. **Per-drone push 粒度**（Q1）— 依 Map Simulator ICD，每架各一筆 `POST /objects/update`，10 架 × 10 Hz = 100 req/s。
2. **LANDED 收尾語意**（Q2）— 切到 LANDED 的同一週期推最後一筆 `flight_state="LANDED"`，之後停推該 drone_id。
3. **REST API 契約範圍**（Q3）— 僅 `POST /command/takeover` 為正式契約；`GET /status/{id}` 與 `GET /drones` 降級為 `--debug` 旗標下的除錯端點。
4. **Scenario timeline action**（Q4）— 封閉白名單 `{start_flying}`；其他值 fail-fast。
5. **Takeover 校驗**（Q5）— 座標/alt 必填+範圍校驗（越界 400）；IDLE 接管回 409；連續接管 200 + 覆寫舊目標。

## 五、Known Issues / Gotchas

1. **Haversine 球面誤差**：自寫公式與 `geopy` Vincenty 在 10–20 km 有 ~0.5% 系統誤差，測試容差 `max(5 m, ref * 0.005)`。
2. **SC 測試窗口縮放**：SC-002/004/007 從 10–30 s 縮到 2 s 以符合 CI 預算，等比例收緊誤差邊界。
3. **structlog `event` 保留字**：原 `state.transition` 的 `event` 欄位改名為 `event_name`。
4. **LANDING flare**：`alt ≤ 2` 時 velocity target 強制 0，避免 ramp 推高速度而觸發不到 LANDED 門檻。
5. **hz 上限 20 Hz**：pydantic 驗證 `update_hz ∈ [1, 20]`。

## 七、下游 feature 的介面契約

**UDS → Map Simulator push payload**（下一個 feature 002 必須接受）：

```json
{
  "drone_id": "TRK-001",
  "lat": 25.058, "lon": 121.565,
  "alt_m": 100.8, "speed_ms": 15.1, "heading_deg": 180.2,
  "status": "FLYING_NORMAL",
  "timestamp": "2026-04-22T08:00:01.000Z"
}
```

**UDS 接管 API**：`POST http://127.0.0.1:8080/command/takeover`  
body `{drone_id, target_lat, target_lon, target_alt_m}`（全必填）；回應 200 / 404 / 400 / 409。詳見 `specs/001-uds/contracts/rest-api.md`。
