# TAK Server — PoC Deployment

This directory hosts the **TAK Server tier** of the CICS Anti-Drone TAK PoC. It
ships two interchangeable profiles in a single `docker-compose.yaml`:

| Profile | Image                                  | When to use                                 |
| ------- | -------------------------------------- | ------------------------------------------- |
| `stub`  | `cics-tak/tak-stub:latest` (built)     | **PoC default.** No TAK.gov account needed. |
| `prod`  | Real `takserver:*` from TAK Product Center | Production / integration test            |

The stub is a self-contained Python asyncio TCP+TLS listener on `:8089` that
accepts newline-delimited CoT XML, logs every event as JSON to stdout, and
optionally appends events to `/var/log/tak-stub/cot.ndjson` for replay. It
exists so developers can exercise the **CoT Gateway → TAK uplink** without an
external dependency. It is **not** a TAK Server replacement — it does not
implement federation, authentication beyond cert validation, the SA cot
fan-out, the web console, or the database.

For full PKI rationale and the production TAK Server contract, see
[`docs/system-docs/07-tak-server-deployment-spec.md`](../../docs/system-docs/07-tak-server-deployment-spec.md)
and [`docs/tak-server-deployment.md`](../../docs/tak-server-deployment.md).

## Quickstart (stub)

```bash
# 1. Generate self-signed PoC certs (one-time, idempotent)
./scripts/gen-certs.sh

# 2. Start the stub
cd infra/tak-server
docker compose up -d

# 3. Tail logs to confirm it is listening
docker compose logs -f tak-server-stub
# expected:
# {"event":"stub_listening","host":"0.0.0.0","port":8089,"scheme":"TLS",...}

# 4. Point the CoT Gateway at it (from another shell, repo root)
export TAK_P12_PASSWORD=takpoc
./scripts/dev-launcher.sh --services cot-gateway \
    --tak-host localhost --tak-port 8089 --tak-use-ssl

# 5. Verify CoT messages arrive
docker compose exec tak-server-stub tail -f /var/log/tak-stub/cot.ndjson
```

To stop everything:

```bash
docker compose down -v   # -v also drops the cot.ndjson volume
```

## Swap to the real TAK Server (production)

1. Obtain the TAK Server Docker image from <https://tak.gov> (account
   required) and `docker load` it on the host.
2. In `infra/tak-server/docker-compose.yaml`, **uncomment** the `tak-server`
   and `tak-db` services, set `TAK_IMAGE` in `.env`, and (optionally) drop
   in your `CoreConfig.xml`.
3. Replace the dev certs in `infra/certs/` with your CA-issued production
   certs, **keeping the same filenames**:
   - `ca.crt`        → your enterprise/TAK CA chain
   - `takserver.crt` / `takserver.key` → server cert/key
   - `gateway.p12`   → CoT Gateway client p12 (password = `$TAK_P12_PASSWORD`)
   - `truststore.pem` → CA chain for clients
4. `docker compose --profile prod up -d`

The CoT Gateway picks up whichever set of certs sits in `infra/certs/`; no
gateway code or config changes are needed.

## File reference

```
infra/
├── certs/                  # Generated by scripts/gen-certs.sh (gitignored)
│   ├── ca.crt              # Root CA (public)
│   ├── ca.key              # Root CA private key — DO NOT COMMIT
│   ├── takserver.crt/.key  # Server cert (used by both stub and prod)
│   ├── gateway.crt/.key    # Client cert (CoT Gateway)
│   ├── gateway.p12         # PKCS#12 bundle consumed by services/cot-gateway
│   └── truststore.pem      # CA chain for ssl.SSLContext.load_verify_locations
└── tak-server/
    ├── Dockerfile          # python:3.12-slim + stub_server.py
    ├── docker-compose.yaml # stub (default) + prod (commented)
    ├── stub_server.py      # asyncio TCP+TLS CoT collector
    └── README.md           # this file
```

## Troubleshooting

| Symptom                                          | Likely cause / fix                                                          |
| ------------------------------------------------ | --------------------------------------------------------------------------- |
| `ssl_error` lines in stub logs                   | Client used wrong CA, expired cert, or mismatched hostname/IP SAN.          |
| `connection refused` from CoT Gateway            | Stub container not running (`docker compose ps`) or port 8089 in use.       |
| `wrong password` opening `gateway.p12`           | `TAK_P12_PASSWORD` env var doesn't match the password used by `gen-certs`.  |
| Stub accepts cleartext but gateway expects TLS   | Don't pass `--no-ssl` to the stub.                                          |
| Real TAK Server rejects gateway client cert      | Production CA must sign `gateway.crt`; reissue `gateway.p12` from your CA.  |
