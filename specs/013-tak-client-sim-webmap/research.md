## Topic 1 — MIL-STD-2525C Icon Shapes (inline SVG)

### Decision
Render MIL-STD-2525C affiliation symbols as inline SVG strings inside Leaflet `L.divIcon({ html: '...' })`. No external image files or new JS libraries.

### Symbol Specifications

#### Unknown affiliation (`a-u-*`) — Grey outlined circle with interior diagonal cross

MIL-STD-2525C Unknown is a circle with an X-cross drawn inside it.

```svg
<svg viewBox="-12 -12 24 24" width="24" height="24">
  <!-- Circle border -->
  <circle r="10" fill="#90a4ae" stroke="#546e7a" stroke-width="2"/>
  <!-- Interior diagonal cross (×) -->
  <line x1="-5" y1="-5" x2="5" y2="5" stroke="#546e7a" stroke-width="1.5" stroke-linecap="round"/>
  <line x1="5" y1="-5" x2="-5" y2="5" stroke="#546e7a" stroke-width="1.5" stroke-linecap="round"/>
  <!-- Optional course arrow when speed > 0.3 m/s -->
  <!-- <g transform="rotate({course})"><polygon points="0,-7 -3,-1 3,-1" fill="white" opacity="0.85"/></g> -->
</svg>
```

Colours: fill `#90a4ae` (Material Blue Grey 300), stroke `#546e7a` (Blue Grey 600).

#### Hostile affiliation (`a-h-*`) — Red filled diamond

MIL-STD-2525C Hostile is a square rotated 45°.

```svg
<svg viewBox="-12 -12 24 24" width="24" height="24">
  <!-- Diamond = square rotated 45° -->
  <rect x="-8" y="-8" width="16" height="16"
        fill="#ef5350" stroke="#b71c1c" stroke-width="2"
        transform="rotate(45)"/>
  <!-- Optional course arrow when speed > 0.3 m/s -->
  <!-- <g transform="rotate({course})"><polygon points="0,-6 -2.5,-1 2.5,-1" fill="white" opacity="0.85"/></g> -->
</svg>
```

Colours: fill `#ef5350` (Material Red 400), stroke `#b71c1c` (Red 900).

**Diamond sizing note**: `<rect x="-8" y="-8" width="16" height="16" transform="rotate(45)"/>` produces a diamond whose vertices sit at (0,±11.3) and (±11.3,0) after rotation. This fits within the `viewBox="-12 -12 24 24"` with a 0.7 px margin. Stroke-width 2 stays visually inside the viewbox.

#### Stale overlay (any shape)

When `evt.is_stale === true`:
- Apply `opacity="0.45"` on the `<svg>` root element
- Override fill colour to `#546e7a` (grey); stale targets are shape-distinct but colour-neutral
- Arrow (if present) is still rendered at the dimmed opacity — last known heading preserved

Implementation: pass stale flag into `makeDroneIcon()`, apply as inline style:
```js
`<svg viewBox="-12 -12 24 24" width="24" height="24" style="${isStale ? 'opacity:0.45' : ''}">`
```
Fill overrides:
- Stale Unknown: fill `#546e7a`, stroke `#37474f`
- Stale Hostile: fill `#546e7a`, stroke `#37474f`

### Rationale
- **Inline SVG over external images**: Avoids CDN requests, works offline, no new `pyproject.toml` dependency (G7). Consistent with the existing SP/HP `L.divIcon` icons in `web_server.py`.
- **`transform="rotate(45)"` on `<rect>` over `<polygon>`**: Cleaner, more readable, same rendering. Polygon alternative (`<polygon points="0,-10 10,0 0,10 -10,0">`) also valid but less maintainable.
- **Colour palette from Material Design**: Matches existing palette already used for tooltips and badges in `web_server.py`.

### Alternatives considered
| Alternative | Rejected because |
|-------------|-----------------|
| PNG sprites (base64 data URI) | Would increase template string by ~3 KB per icon; no benefit vs inline SVG |
| CSS `clip-path: polygon(50% 0%, 100% 50%, 50% 100%, 0% 50%)` | Diamond clipping works but gives no stroke control; harder to add arrow inside |
| External SVG file via `L.icon({ iconUrl: '/static/hostile.svg' })` | Requires static file serving endpoint — additional route, additional complexity |
| Leaflet.EasyButton / Leaflet plugins | G7 violation — new JS library |

## Topic 3 — `asyncio.open_connection` with `ssl=None` (plaintext TCP)

### Decision
Pass `ssl=None` to `asyncio.open_connection` when `config.use_ssl` is `False`. The existing call already passes `ssl=ssl_ctx`; the change is to conditionally set `ssl_ctx = None`.

### Findings
- Python docs: "If ssl is `None`, no SSL/TLS is used." — the connection is a plain TCP socket.
- `asyncio.open_connection(host, port, ssl=None)` is equivalent to `asyncio.open_connection(host, port)` — the keyword argument defaults to `None` anyway. Being explicit is clearer.
- `ssl.SSLContext` construction in `build_ssl_context()` is skipped entirely when `use_ssl=False`, avoiding an unnecessary `ssl.PROTOCOL_TLS_CLIENT` context that would error on a plaintext server.
- The `except (OSError, ssl.SSLError, ConnectionRefusedError)` catch in the retry loop already handles both SSL and non-SSL error types correctly.

### Implementation
```python
async def connect_with_retry(config, stats, stop):
    ssl_ctx = build_ssl_context(config) if config.use_ssl else None
    while not stop.is_set():
        try:
            reader, writer = await asyncio.open_connection(
                config.host, config.port, ssl=ssl_ctx, limit=65536
            )
```

### Alternatives considered
| Alternative | Rejected because |
|-------------|-----------------|
| Separate `connect_plaintext()` function | Duplication; the only difference is one argument |
| Env variable override | Less explicit than a config field; breaks `pydantic` validation |

## Topic 4 — Port conflict detection in Bash (pre-flight)

### Decision
Use `bash -c "echo > /dev/tcp/127.0.0.1/${port}" 2>/dev/null` to test if a port is occupied. If the TCP connect succeeds (exit 0), the port is in use.

### Findings
- `/dev/tcp` is a bash built-in available on Linux and macOS without any extra tools.
- Alternative `ss -ltn | grep -q ":${port} "` works on Linux but requires `ss` (not always present on macOS).
- `lsof -i :${port}` requires elevated privileges in some environments.
- The existing `demo-cot-gateway-map.sh` already uses `bash -c "echo > /dev/tcp/127.0.0.1/18080" 2>/dev/null && UDS_OK=true` for health checks — reuse the same idiom for pre-flight.

### Helper function pattern
```bash
check_port_free() {
    local port=$1 label=$2
    if bash -c "echo > /dev/tcp/127.0.0.1/${port}" 2>/dev/null; then
        die "Port ${port} (${label}) is already in use. Stop the conflicting service first."
    fi
}
```

## Topic 5 — `tak_relay.py` health check (TCP connect)

### Decision
Use the same `/dev/tcp` TCP connect as above to health-check the TAK relay, since it has no HTTP health endpoint.

### Findings
- `tak_relay.py` is a plaintext TCP broadcast relay with no HTTP API.
- Health check: `bash -c "echo > /dev/tcp/127.0.0.1/8089" 2>/dev/null && RELAY_OK=true`.
- This is the same approach the reference script uses for UDS (port 18080).
